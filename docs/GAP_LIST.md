# Slermes Desktop & Surface Parity — Fresh Gap List (2026-08-03)

> Generated by a full-project parity audit. The "no gaps" assumption was
> wrong — the desktop app contained substantial dead code and the CLI
> command surface was missing Python-registry commands. This document is the
> live gap list; items are closed as they are implemented.

## How this audit was run

- CLI surface: compared Python's authoritative `COMMAND_REGISTRY`
  (`hermes_cli/commands.py`, 84 commands) against the C dispatch table
  (`src/cli/commands.c` COMMANDS[]) and the auto-generated registry port
  (`src/cli/port_cli_command_registry.c`).
- Desktop: DA audit scripts (pass1/pass2/pass3) updated to scan the full
  modular GUI set (desktop_gui.c is a thin entry since the modular refactor).
- Dead-code scan: every exported function checked for callers.

## 🔴 Open gaps (ranked)

### P0 — correctness / real behavior
1. **MOA engine**: `moa_create()` in port_moa_loop_ports.c is a stub
   (`printf` + `strdup("{}")`). `/moa` delegates to a wrapper that calls it.
   Port `agent/moa_loop.py:create` for real.
2. **Pet generation pipeline**: `/hatch` delegates to the wrapper, but the
   image-model generate step (`agent/pet/generate/orchestrate.py`) has no C
   backend. `pet_atlas` + `port_pet_prompts` exist; the orchestration +
   image-gen provider call is missing.
3. **`cli_u_handle_battery_command` / `cli_u_battery_status_style`**
   (port_cli_wrappers.c) are `(void)req; return json_object();` stubs.
4. **`hermes_cli_journey_cmd_journey`** wrapper needs verification that its
   underlying journey storage read is real (not printf-only).
5. **nous billing/subscription**: `/subscription` + `/topup` print
   portal-hint text; real account/balance read not wired (port_nous_billing
   exists — verify).
